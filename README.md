# Магазин відеоігор (gamestore)

Навчальний проєкт на Spring Boot 3.4, Java 21, Maven. Поки що лише backend, дані зберігаються в пам'яті.

## Ендпоінти

| Метод  | Шлях                    | Що робить                              | Коди              |
|--------|-------------------------|----------------------------------------|-------------------|
| GET    | `/api/games`            | перелік карток ігор                    | 200               |
| GET    | `/api/games?genre=...`  | перелік ігор одного жанру              | 200               |
| GET    | `/api/games/{id}`       | одна гра з деталями                    | 200 / 404         |
| POST   | `/api/games`            | створити гру                           | 201 / 400         |
| PUT    | `/api/games/{id}`       | оновити гру                            | 200 / 400 / 404   |
| DELETE | `/api/games/{id}`       | видалити гру                           | 204 / 404         |

Приклади `curl` для всіх операцій і помилок — у [requests.md](requests.md).

## Модель `Game`

| Поле          | Тип          | Де видно           | Валідація (`GameRequest`) |
|---------------|--------------|--------------------|---------------------------|
| `id`          | `Long`       | картка, сторінка   | задає сервер              |
| `title`       | `String`     | картка, сторінка   | не порожня                |
| `platform`    | `String`     | картка, сторінка   | не порожня                |
| `price`       | `BigDecimal` | картка, сторінка   | обов'язкова, > 0          |
| `coverUrl`    | `String`     | картка, сторінка   | —                         |
| `developer`   | `String`     | сторінка           | не порожній               |
| `releaseYear` | `Integer`    | сторінка           | > 0                       |
| `genre`       | `String`     | сторінка, фільтр   | не порожній               |
| `ageRating`   | `Integer`    | сторінка (PEGI)    | від 0 до 18               |
| `description` | `String`     | сторінка           | —                         |

## Помилки

Усі помилки повертаються в одному форматі `ErrorResponse` — його формує глобальний
`GlobalExceptionHandler` (`@RestControllerAdvice`):

```json
{ "status": 404, "error": "Not Found", "message": "Гру з id=999 не знайдено", "details": [] }
```

- `404` — гри з таким id немає (`GET`, `PUT`, `DELETE`);
- `400` — тіло не пройшло валідацію (у `details` перелік проблем по полях), зламаний JSON
  або id — не число.

## Структура

```
com.ua.gamestore
├── config       GameSeeder — початкові ігри
├── domain       Game — доменна модель
├── exception    GameNotFoundException
├── repository   GameRepository (інтерфейс) + InMemoryGameRepository
├── service      GameService (інтерфейс) + GameServiceImpl
│   └── mapper   GameMapper — Game ↔ DTO
└── web          GameController, GlobalExceptionHandler
    └── dto      GameCardDto, GameDetailDto, GameRequest, ErrorResponse
```

## Запуск

```bash
./mvnw spring-boot:run
```

## Тести

```bash
./mvnw test
```

> Потрібна **Java 21** (або 23). Під Java 25 Mockito не працює — перед запуском вкажіть
> `JAVA_HOME` на JDK 21/23.

Перевірка автономності — випадковий порядок тестів:

```bash
./mvnw test '-Djunit.jupiter.testmethod.order.default=org.junit.jupiter.api.MethodOrderer$Random'
```

(Аргумент в одинарних лапках — так команда працює і в bash, і в PowerShell; у PowerShell
пишіть `.\mvnw.cmd` замість `./mvnw`.)

### Рівні тестів (піраміда)

| Рівень | Клас | Що піднімає | Залежності | Тестів |
|---|---|---|---|---|
| Unit | `GameServiceImplTest` | нічого (`new`) | репозиторій — `mock()` | 10 |
| Unit | `GameMapperTest` | нічого | немає | 3 |
| Integration — зріз | `GameControllerTest` | лише веб-шар (`@WebMvcTest`) | сервіс — `@MockBean` | 13 |
| Integration — наскрізний | `GameApiIntegrationTest` | весь застосунок (`@SpringBootTest`) | реальні | 8 |
| Smoke | `GamestoreApplicationTests` | весь застосунок | реальні | 1 |

Наскрізний тест **автономний**: перед кожним тестом `repository.deleteAll()`, кожен тест сам
створює свої ігри через API й перевіряє лише їх. Стартові ігри з `GameSeeder` у тестах не
використовуються.

### Звіт про покриття

| Сценарій | Unit | Зріз | Наскрізний | Результат |
|---|:---:|:---:|:---:|---|
| Перелік ігор | ✅ | ✅ | ✅ | 200, масив карток |
| Фільтр за жанром (і без урахування регістру) | ✅ | ✅ | ✅ | 200, лише цей жанр |
| Порожній / пробільний жанр = без фільтра | ✅ | — | — | усі ігри |
| Порожній магазин | — | — | ✅ | 200, `[]` |
| Одна гра, існує | ✅ | ✅ | ✅ | 200, деталі |
| Одна гра, не існує | ✅ | ✅ | ✅ | 404 + тіло помилки |
| Id — не число (`/api/games/abc`) | — | ✅ | — | 400 + тіло помилки |
| Створення валідної гри | ✅ | ✅ | ✅ | 201, новий id |
| Створення невалідної гри | — | ✅ | ✅ | 400 + `details`, нічого не збережено |
| Зламаний JSON | — | ✅ | — | 400 + тіло помилки |
| Оновлення, гра існує | ✅ | ✅ | ✅ | 200, той самий id |
| Оновлення, гри немає | ✅ | ✅ | — | 404, нічого не збережено |
| Оновлення невалідними даними | — | ✅ | — | 400 |
| Видалення, гра існує | ✅ | ✅ | ✅ | 204, потім 404 |
| Видалення, гри немає | ✅ | ✅ | ✅ | 404 |
| Мапінг `Game` ↔ DTO | ✅ | — | — | правильні поля, `id` не з запиту |

**Що не покрито і чому:**

- **`GameSeeder`** — стартові дані не перевіряються тестами навмисно: тести мають бути
  незалежні від того, які ігри лежать у магазині при запуску.
- **Одночасні запити** (кілька клієнтів змінюють ту саму гру) — для in-memory сховища на
  `ConcurrentHashMap` це не критично, а в Модулі 2 цим займатиметься база даних.
- **Реальний HTTP-сервер і мережа** — `MockMvc` обробляє запити без запуску Tomcat; запуск
  сервера й `curl` перевірено вручну за `requests.md`.
- **Робота з базою даних** — бази ще немає. Коли репозиторій заміниться на PostgreSQL
  (Модуль 2), саме `GameApiIntegrationTest` почне перевіряти роботу з нею.
- **Швидкодія та навантаження** — нефункціональні тести не входять у цей модуль.
